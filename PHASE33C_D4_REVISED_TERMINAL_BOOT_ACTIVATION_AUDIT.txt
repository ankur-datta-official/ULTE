Previous D4 hard stop and revised design
The previous D4 audit correctly found that a bare FAILED_NOT_SUBMITTED broker row
and PENDING effect cannot reconstruct TerminalNonSubmissionProofV1. The revised
design resolves that semantic question: DB-only boot must reject that historical
proof-missing state, never fabricate a proof or emit
TERMINAL_NON_SUBMISSION_REQUIRED. A complete D3/D3N terminal tuple could instead
return TERMINAL_NON_SUBMISSION after coherent validation.

Blocking invariant: coherent boot snapshot is unavailable through the current
PostgresExecutor abstraction.
packages/orchestration-state-store-postgres/src/postgres.ts exposes only
transaction(work), with no isolation-level contract or option. Its real
PostgreSQL test implementation in tests/integration/b1f-postgres-helper.ts begins
a pinned transaction, explicitly sets READ COMMITTED, and executes SELECT
pg_backend_pid() before invoking work. Consequently a D4 callback cannot safely
set REPEATABLE READ before the transaction's first query. Several authority
components require separate reads. READ COMMITTED can see a D3/D3N commit
between those reads and produce a mixed pre/post-commit tuple. No existing
revision double-check/reload algorithm establishes an equivalent snapshot.
Task045 section 16 explicitly requires HARD STOP if the current transaction
abstraction cannot set REPEATABLE READ safely. A new executor isolation contract
and its implementation must be designed and reviewed before boot activation.

Architecture discovered
packages/sandbox-orchestration-recovery/src/classify.ts is the pure C1
classifier. packages/sandbox-orchestration-recovery/src/types.ts defines
RecoveryBootResult, including future terminal variants. No production boot
loader or runtime dispatcher calls the classifier. PostgreSQL stores supply
individual recovery, lease, checkpoint, pending, outcome, broker idempotency,
and immutable receipt reads, including transaction-bound functions. D3 and D3N
commit terminal facts atomically in one pinned write transaction. The old
execution runtime has not been cut over to D3N.
