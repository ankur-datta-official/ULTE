Transaction: BEGIN; verify the complete D2C ledger/catalog capability and exact
database/schema/search_path on this transaction connection; read terminal receipt by
disposition ref, session, and exact broker identity; validate historical retry if found;
lock and check lease using database time; recheck receipt after lease serialization;
lock recovery and validate revision, fence, checkpoint and frozen authority;
lock linked pending effect and validate its creation receipt and checkpoint ancestry;
lock exact broker idempotency row; require FAILED_NOT_SUBMITTED and no adapter order ID;
reject linked canonical outcome and ambiguous or accepted/rejected broker disposition;
insert immutable terminal receipt; resolve pending as
TERMINAL_NON_SUBMISSION with disposition ref, committed revision and unchanged fence;
CAS recovery to V2 with revision +1 and terminal ref only; check unchanged authority;
recheck lease at database time; COMMIT. No provider or broker I/O is performed.

Global lock order follows existing fenced writers: lease, recovery, pending, broker,
receipt. Creation receipt/checkpoint and outcome reads do not lock. The early receipt
lookup is a read; the post-lease recheck converges concurrent identical callers.

Task042A final source audit found the original concurrency proof insufficient. The
identical and conflicting Promise.all tests could pass through sequential execution;
the old adoption case seeded a linked canonical outcome that independently rejected
D3 before any race. Task042B hardened tests only. A's afterQuery hook pauses immediately
after the real lease SELECT FOR UPDATE while its physical transaction retains that row
lock. B's beforeQuery hook proves the conflicting lease SELECT FOR UPDATE is issued on
a different backend. The observer calls pg_blocking_pids(B_PID), requires A_PID among
the blockers, and verifies its own backend differs from both workers before A is
released. All barriers are bounded and hooks are cleared in finally blocks.

Identical D3 race: A returns COMMITTED; B returns ALREADY_COMMITTED. Conflicting D3
race: A returns COMMITTED; B returns RECEIPT_CONFLICT. Each leaves one immutable
receipt, one terminal pending resolution, one recovery revision advance and the exact
terminal reference.

LEGAL_D3_ADOPTION_RACE = YES. A definite non-submitted entry cancellation can be
closed while an unlinked entry fill is independently adoptable. The revised test
starts from this coherent state, proves the adoption checkpoint advance with the
domain authority proof, then observes adoption's lease query blocked behind D3's
lease row lock. D3 commits; adoption deterministically fails TERMINAL_STATE_CONFLICT.
The final database contains only terminal authority, with no adoption receipt or
mixed recovery state. The old pre-existing linked-outcome race claim is superseded.

Fresh writes require current lease owner, exact DB-issued fence, nonexpired lease,
and lease/recovery fence synchronization. The final check rolls back all writes on
expiry. Historical retries compare the complete D1 logical payload and ignore the
current owner/fence, as required by the frozen D1 contract. Conflicting reuse fails.

The exact broker triple is adapter_id, environment, idempotency_key. The broker row
must match operation, attempt and fingerprint and be FAILED_NOT_SUBMITTED. No status
transition, retry authorization, or canonical rejection is invented. The current D1/D2
contracts separate normal-flow status persistence from historical D3 closure; this API
closes the already durable FAILED_NOT_SUBMITTED + PENDING state.
